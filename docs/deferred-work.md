- source_spec: `docs/spec-1-2-registro-de-presenca-falta-por-turma-e-data.md`
  summary: In `Presenca.tsx`, `handleSave`'s stale-write guard only checks whether the selected classroom changed while a save is in flight, not whether the selected date changed. Changing the date (with the classroom unchanged) while a save request is still pending can attach a misleading "Registro salvo." confirmation to a row the user now sees for the new date, even though the record was actually written against the previous date.
  evidence: In `frontend/src/pages/Lancamento/Presenca.tsx`, the enrolled-students effect (`useEffect(..., [token, selectedClassroomId, date])`) re-fetches and resets `rowStates` to fresh defaults whenever `date` changes, but `handleSave`'s post-await guard (`if (selectedClassroomIdRef.current !== classroomIdAtSaveStart) return`) only tracks `selectedClassroomId` via `selectedClassroomIdRef` -- there is no equivalent ref/guard for `date`. Sequence: select turma+date A, click Save for a student (POST in flight), change the date field to B before the response resolves -- the effect resets that student's row to its default (unsaved) state for date B, then the still-pending POST for date A resolves and calls `updateRow(studentId, { message: 'Registro salvo.' })`, painting a "saved" confirmation onto the row the user is now viewing for date B, which was never actually submitted. This is the same class of stale-closure bug as Pass 1 findings #6/#8 in this spec's Review Triage Log (which fixed the analogous classroom-switch and missing-date-dependency cases) but for the specific combination of "date changed, classroom unchanged, save in flight" that those two patches don't jointly cover. Narrow timing window (requires a save round-trip slower than the also in-flight roster re-fetch), same reachability class as the already-logged/patched #7 and #8 -- not blocking, but worth closing alongside those in a follow-up (e.g. a `dateRef` mirroring `selectedClassroomIdRef`, or keying `rowStates` by `{classroomId}:{date}:{studentId}`).
